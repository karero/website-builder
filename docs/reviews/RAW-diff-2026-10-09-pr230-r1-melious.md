## Independent review — melious (kimi-k3, HTTP API)


- BUG — skills/facts-check/scripts/facts_check.py `PageText.handle_startendtag` / `handle_starttag`: a self-closing script tag (`<script src=.../>` or `<script type="application/ld+json"/>`) leaves the parser permanently stuck — SKIP_TAGS `+1` is never reversed because the fix-up in `handle_startendtag` explicitly excludes `"script"`, and the ld+json branch sets `_in_ldjson = True` with no matching close. Every `handle_data` after such a tag is routed to `_skip`/`_ld_buf`, so all subsequent page text, h1s and intros vanish: wrong "fact named nowhere"/missing findings and false positioning failures for the rest of the page, silently. Fix: in `handle_startendtag`, for script with ld+json type flush `_add_ldjson("".join(_ld_buf))` and clear `_in_ldjson`; for plain script apply the same `_skip` decrement as the other SKIP tags.
- RISK — same file `PageText.handle_starttag` (`elif tag == "p" and self._p_buf is None`, the `tag in self._first_at` branch, h1 capture): none of the main/article/p/h1 bookkeeping checks `_self._skip`, so block structure *inside* `<noscript>`, `<template>`, `<svg>`, `<iframe>` or `<canvas>` still registers: a `<p>` inside such an element claims `first_p["body"]/["main"]` with an empty buffer (its data is correctly dropped), which then blocks the real first paragraph from ever being captured (`self.first_p[k] is None` is already false). A page composed with a `<template>`/`<noscript>` containing main/p therefore gets an empty intro and fails every positioning h1/intro clause — a false finding on ordinary markup. Fix: gate the first_at/p/h1/slots logic on `self._skip == 0` (mirror the `handle_data` early-return), or unwrap only the allowed tags while skipping.
- RISK — .github/workflows/clean.yml new `facts-check-tests` job, `uses: actions/checkout@v7` / `actions/setup-python@v7`: the diff contains no evidence these major-version tags exist (the surrounding jobs' pins are not shown), and if `@v7` is not a published tag the job errors at the first step, failing the whole `clean` workflow on every push/PR. Fix: match the major tag the other jobs in this file already pin (or point at a verified released tag/SHA).
- NIT — skills/facts-check/SKILL.md facts-field table vs facts_check.py: `owner` and `checked` are documented as load-bearing provenance ("who vouches for it, when it was last confirmed") but the script never reads or validates either (only `source` is printed); a facts file missing/staling them still passes. - NIT — facts_check.py `Fetcher.allowed`: any non-200 robots.txt answer other than 401/403 becomes `allow_all`, including 5xx and fetch errors; the robots convention treats server errors as full-disallow, so a flaky robots endpoint makes this read-only checker crawl sections the site asked crawlers to avoid. Fix: disallow-all (or skip with a note) on 5xx/unreachable robots.
